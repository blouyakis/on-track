# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

OnTrack: a shared contribution log for teams (CS6983 AI Coding, Fall 2026, Project 3). Overseers create projects and share an invite code; Contributors join and log entries (date, hours, type, details, optional link; meetings also record attendees, decisions, action items). The product spec, roles, validation rules, and out-of-scope list live in `docs/PRD.md`. Read it before building a feature, and treat its "Rules the logic must enforce" section as the source of truth for business logic and the primary target for tests.

The app is currently the untouched `create-next-app` scaffold; all product code is still to be written.

## Commands

Node 26 (`.nvmrc`). npm is the package manager (`package-lock.json`).

```bash
npm run dev          # next dev at http://localhost:3000
npm run build        # production build
npm run lint         # eslint (flat config, eslint-config-next core-web-vitals + typescript)
npx tsc --noEmit     # type check (no npm script for this)
npm test             # vitest run (single pass)
npm run test:watch   # vitest in watch mode
npx vitest run src/lib/__tests__/sanity.test.ts   # one file
npx vitest run -t "test runner works"             # one test by name
```

Definition of done from the PRD: tests written before implementation and passing, lint and type check passing, server-side input validation, PR reviewed by the other partner.

## Next.js version warning

This repo runs Next.js 16.4 with `cacheComponents: true` and `partialPrefetching: true` in `next.config.ts`. Caching, data fetching, and auth patterns differ from older App Router versions. Before writing server code, consult the bundled docs at `node_modules/next/dist/docs/01-app/` (notably `01-getting-started/06-fetching-data.md`, `08-caching.md`, `07-mutating-data.md`, and `02-guides/authentication-with-cache-components.md`). `AGENTS.md` in the repo root is regenerated by `next dev` and carries the same instruction.

## Structure and conventions

- `src/app/` is the App Router root. `@/*` maps to `src/*` (tsconfig and vitest both resolve it).
- `src/lib/` holds framework-free logic; tests live beside it in `__tests__/`. Put the PRD's visibility, summary, and validation rules here as pure functions so they can be unit-tested without React or a server.
- Vitest uses jsdom and `@vitejs/plugin-react`; `@testing-library/react` and `@testing-library/dom` are installed for component tests.
- Tailwind CSS v4 is wired through the `@tailwindcss/turbopack` loader in `next.config.ts`, not a PostCSS config. Global styles are in `src/app/globals.css`. The root layout uses `LayoutProps<"/">` (a Next-generated type) and the Geist fonts via `next/font/google`.
- Layout note: `<html>` is `h-full` and `<body>` is `min-h-full flex flex-col`, so page roots should use `flex-1` to fill the viewport.
